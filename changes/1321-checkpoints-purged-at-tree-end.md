**An ended tree's checkpoints are deleted with it** (#1321d, Q11): `forgetTree` removes the root's checkpoint thread and every child thread (`<root>/child/<id>`, at any depth) through the application's saver, so `deleteThread(rootExecutionId)` of a saver now removes the whole tree and only it (the checkpoint saver contract has a case). A finished tree is read from its kept record alone: `DurableExecutionStatus.Finished` read from an answered record has the finish of its route's last node and its cost, no output and no tokens; the A2A task projection takes the finish and output from its end event. A tree whose end is still being recorded (record not yet answered) is still read from its last checkpoint.
**A tree is deleted by its root id, never by a range of thread ids; `/child/` is reserved** (#1321d, security): a client that could pick an id holding the child separator or sharing its prefix could have deleted another tree's checkpoints. (1) `KeyTextRule.ReservedSeparator` (`reserved-separator`): no key text — a thread id, an execution id (A2A and MCP provided ones, `withReservedExecutionId`), a minted id, a tenant id, a business key — holds `/child/`; it is refused with the rule named, never the id. (2) Every checkpoint and pending write stores its tree's root execution id (`configurable.root_execution_id`, written by the framework for every run, child and remote child; else the first segment of the thread id) in a `root_id` column of the SQLite baseline tables (edited in place), and `deleteThread(root)` of the SQLite and in-memory savers deletes `thread_id = ? OR root_id = ?`. `childThreadRangeOf` and `isChildThreadOf` are removed.
**Store follow-up (T-train):** a saver of a store package stores the tree's root with each checkpoint and write (`configurable.root_execution_id`, a column / field / key set of its own, indexed) and `deleteThread(rootExecutionId)` deletes the thread and every thread whose stored root is that id — PostgreSQL `root_id` column created after `PostgresSaver.setup()` (not in a numbered migration), MongoDB a field with an index, Redis a set of the root's threads; never a range or a prefix. The `checkpointSaverContract` case puts threads with `root_execution_id` and keeps `root/child/x-evil` and `root0` trees.
