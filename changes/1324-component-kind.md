section: Breaking
issue: 1324

**One `ComponentKind` for every component; `NodeKind` is removed** (#1324): the enum has all 41 kinds (`Application`, `Workflow`, `WorkflowStart`, `WorkflowFinish`, `Agent`, `Action`, `Router`, `Arbiter`, `Tool`, `ToolInterceptor`, `ToolApproval`, `ExternalTask`, `Channel`, `ChannelSelector`, `WorkingCalendar`, `ChannelListener`, `ChannelInterpreter`, `Memory`, `Rag`, `RagReranker`, `Guardrail`, `Injectable`, `PiiPolicy`, `FilePolicy`, `FileMasker`, `FileTranscriber`, `Judge`, `EvalSuite`, `Budget`, `ModelProvider`, `DatabaseStorage`, `ClusterStorage`, `ObjectStorage`, `Mesh`, `HttpAuthenticator`, `Observer`, `HealthCheck`, `McpServer`, `McpEndpoint`, `A2AAgent`, `A2AEndpoint`), and every value is the exact kebab-case name of its decorator, the suffix of the component's `name`. Two stored strings change: `ComponentKind.ExternalTask` is `"external-task"` (was `ComponentKind.Question`, `"question"`) and `ComponentKind.ChannelInterpreter` is `"channel-interpreter"` (was `"reply-interpreter"`). A stored `ComponentRecord.kind` (execution records, `agboss describe --json`, eval reports, observer events, the `component.kind` of a trace) carries the new strings, and nothing reads the old ones: a record written by an earlier build keeps its old `kind`, and a store that holds such records must be emptied or migrated by its owner. Removed: `NodeKind` (`Start` is `ComponentKind.WorkflowStart`, `Finish` is `ComponentKind.WorkflowFinish`, `Question` is `ComponentKind.ExternalTask`, the others keep their names) and `ComponentKind.Question`. The kinds of a flow path stay one internal union, `FlowNodeKind`, so a `switch (node.kind)` in the flow engine is still exhaustive for TypeScript. The brand `.agboss/types.d.ts` puts on a component class is `{ name, kind: ComponentKind.X }`; regenerate it with `agboss check`. The channel interpreter's vocabulary follows: the rule `[reply-interpreter.decision-model]` is `[channel-interpreter.decision-model]`, its cost caller `reply-interpreter:<name>` is `channel-interpreter:<name>` (`spend.byCaller`, `TurnUsage.caller`, `ModelStartEvent.caller`, and the key of `mockModel(...).scriptOf(...)`), and the model-call user kind the scripted gateway reads is `"channel-interpreter"`; `TurnFor` (and so `mockModel(X).thenReturn(...)`) finds an interpreter by its `ComponentKind`, not by a `-reply-interpreter` name suffix, and the layout of an interpreter is `channel-interpreters/<name>/<name>.channel-interpreter.ts`. **Before updating, merge or cancel the open runs:** a run checkpointed by an earlier build (the checkpointer / state store) holds `kind: "question"` inside its state, and a pause row or history record with an old `kind` is refused (`StoreError.UnreadableRecord`); no marker or compatibility reader is added.
