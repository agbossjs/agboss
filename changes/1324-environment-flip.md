section: Breaking

**The environment contract is gone; a profile selects the configuration and `defineEnv` holds the variables** (#1324, part b flip) — `@Application({ environment })`, `AppEnvironment` classes, `EmptyEnvironment`, `EnvironmentField` / `@Injectable({ environmentFields })`, `SecretFieldOf`, `@Application({ piiKeyField })`, `env.flag`, `ApplicationContext.environment` / `.environmentName`, the generated `Environment` type and the `environments/<name>.environment.ts` files with their loader are removed, and so are `EnvironmentErrorCode` and `ConfigError.Environment`'s `envCode`. `createApp`, `studioOf`, `describeApplication`, `testWith` and `testModule` select by `{ profile?: string | readonly string[] }` (`src/config/<name>.config.ts|yaml`, as `agboss --profile`); the old `{ env: "prod" }` that named an environment file is gone. The `env` option of `testWith`, `testModule` and the unit runners now takes only `configureEnv(appEnv, { … })` overrides of `defineEnv` variables. A component reads the resolved values with `deps: [appEnv]` (`testApp.get(appEnv)` in a test); `ApplicationContext` keeps `name`, `version`, `instanceId`, `startedAt`, `profiles` and `host`, and gains no `env`. A `defineEnv` variable that is unset or does not parse is `ConfigError.Environment` (`config.environment`), its message naming the rule `[environment.missing-variable]` or `[environment.invalid-value]`, the variable and never a value. `SqliteConnection`, `S3FileRepository` and `LocalDiskFileRepository` read their settings only from the application's storage (`@DatabaseStorage({ driver: SqliteDriver({ path }) })`, `@ObjectStorage({ driver: S3Driver(…) | LocalDiskDriver(…) })`) — no store field of the environment, and with no such storage a SQLite store fails the start naming the storage to declare. The PII key is `@DatabaseStorage({ piiSecret })` and the idempotency key `idempotencySecret`; the rules `[environment.contract-value]`, `[environment.missing-field]`, `[environment.conflicting-field]` and `[storage.key-conflict]` are gone, and `EvalRunReport` no longer has `environment` (it has `profile`). The fault suite's `FaultStoreSet.environment` is `storage` (`{ backend, settings }`). Migration: replace each environment file with `defineEnv` and a `src/config/<name>.config.ts` profile (`configureEnv` for the values that differ), read it with `deps: [appEnv]`, and move a store's file or bucket into the storage's driver.
