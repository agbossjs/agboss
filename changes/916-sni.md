**A file fetch names its host in the TLS handshake, and no longer refuses under APM agents**
(#916, after the spec review of #1010): the own connection of the file fetch started TLS on an
existing socket, which sends no SNI, so a CDN or virtual host (Cloudflare, CloudFront, GitHub, S3)
aborted the handshake or served its default certificate and the fetch failed with a certificate
mismatch. The ClientHello now carries the host as `servername` (none for an IP-literal url, which
TLS does not allow). The "stack probe" that refused when `net`, `tls` or `ClientRequest` looked
patched is removed: APM and tracing agents (dd-trace, New Relic, OpenTelemetry) wrap exactly
these, so every file fetch under them failed with a false `a2a.file-address-denied`. The guarantee
is the check of the raw socket's peer — its remote address compared exactly with the address the
guarded resolver returned, plus the deny list, before any byte — so a wrapper that preserves
behaviour works, and one that reroutes the connection is refused with nothing sent. The
connection is now made before the request is built, so a denied address never constructs a
request, and a request that has an agent (a replaced `ClientRequest`) is destroyed together with
the connection and refused. Pinned by tests with a local TLS server that serves by SNI, an
APM-style wrapper, a rerouting wrapper and a request with an agent.
