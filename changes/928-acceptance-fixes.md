**The store-call bound, after its acceptance** (#928, #1058, #1060, #1061): a bounded call that returns an async iterator (the checkpoint saver's `list`) no longer waits for ever: each `next()` is bounded on its own, a step that does not answer ends the consumer's `for await` with `StoreCallTimeoutError` (or the hand-over, under a lease), and the source's `return()` is started, never awaited behind the hung step. A store's own command timeout (`StoreCallTimeoutError` with `source: StoreOutcomeSource.Command`) is now counted in `agboss.instance.store_calls.timed_out` (`source="command"`) and logged as `store.call-timeout`, as the framework's bound is. The lease renewal's own bound is 5 s, below the 15 s of any other call: a store's command timeout above 5 s never fires first for `renew`. The explorer's watchdog names the action that hung, not the first one it watched. Once a tree's terminal record is durable (finished, failed or cancelled), a lease release that fails or hangs no longer replaces the run's result with a store error: the caller gets the real result, the failure is logged as `execution.lease-release-failed`, and the lease expires in its store (a client without an idempotency key would otherwise retry a run that had charged). The fault suite gained bounded variants of its freeze scenarios (5, 5b, 5c, 5d, 17, 17b) and scenarios 17c and 17d, and a frozen pod now stops itself between two turns of its event loop (a stop from outside could land inside a SQLite transaction and leave the file locked: a rare hang of the scenarios).
